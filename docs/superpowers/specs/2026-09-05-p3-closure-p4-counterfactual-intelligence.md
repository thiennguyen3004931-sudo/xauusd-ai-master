Close P3 with a production-acceptance verifier and correct the stale Fast-Move contract representation, then add a read-only P4 Shadow/Counterfactual Intelligence layer that compares observed outcomes with evidence-gated alternatives without changing LIVE strategy, risk, orders, positions, mode, ARM, or configuration.

## P3 closure defect to fix
Two P3 paths still encode the previous Fast-Move giveback contract:
- `phase7c-performance-effectiveness.service.ts` returns TREND `6` / SIDEWAY `4` from `fastMoveContract(...)`.
- `Phase7CPerformanceEffectivenessCard.tsx` displays TREND `6` / SIDEWAY `4` in the user-facing info alert.

## P3 production acceptance verifier
Add a dedicated GET-only/read-only PowerShell verifier that runs against localhost production and proves:
- exact accepted runtime source attestation is 8/8;
- P3 endpoint is reachable over GET only;
- `schemaVersion=phase7c-performance-effectiveness-v1`;
- `readOnly=true`;
- every P3 safety mutation flag is false and `autoRetune=false`;
- zero-row snapshots are valid and must not be rejected merely for lack of samples;
- the returned current Fast-Move contract, when rows exist, is activation `10` / giveback `10` for both strategies;
- the verifier itself performs no restart, mode change, ARM change, order mutation, position mutation, or LIVE test order.

The verifier must fail closed on schema/safety/contract mismatch. A production acceptance result may be claimed only from output generated by this verifier against the production host; source/CI success alone is not production acceptance.

## P4 architecture
P4 is an evidence-gated counterfactual engine built on P3 rows. It never mutates execution state. Every alternative is classified by what the evidence can actually prove.

### Evidence verdicts
- `EXACT`: ordered evidence is explicitly proven complete and valid, and is sufficient to replay the alternative without inventing intrabar ordering.
- `BOUNDED`: explicit observed evidence allows a bounded alternative metric, but not a full counterfactual exit/PnL claim.
- `UNAVAILABLE`: the required evidence does not exist, is incomplete/invalid, or identity is not exact.

Unknown values remain `null`; the engine must never infer missing PnL, exit price, or intrabar ordering from M5 OHLC.

### Canonical schema
Create `phase7c-counterfactual-intelligence-v1` with:
- `tradeKey`, `positionId`, strategy, side, regime and entry type;
- `scenarioId` and `family`;
- baseline and alternative parameter descriptions;
- evidence verdict and evidence sources;
- observed actual outcome;
- shadow outcome with nullable fields;
- delta metrics with nullable fields;
- quality warnings;
- hard safety object with `readOnly=true`, `shadowOnly=true`, `autoApply=false`, `autoRetune=false`, and every runtime/order/strategy/risk mutation flag false.

### Initial scenario families
1. `FAST_MOVE_GIVEBACK`
   - baseline activation `10`, giveback `10`.
   - shadow giveback grid initially `4, 6, 8, 12` for both TREND and SIDEWAY.
   - replay may be `EXACT` only when the pure evaluator receives canonical ordered exit-side samples together with an explicit completeness assertion and the samples are valid with strictly increasing timestamps.
   - a non-empty but incomplete/invalid ordered stream must never be promoted to `EXACT`; explicit management evidence may still support a separate `BOUNDED` locked-profit-floor comparison.
   - if only explicit Fast-Move management events exist, derive bounded locked-profit-floor comparisons from explicit peak/stop evidence, mark `BOUNDED`, and leave hypothetical exit/PnL deltas null.
   - with no qualifying evidence, mark `UNAVAILABLE`.

2. `RULE_OBSERVATION`
   - enumerate passed/blocked rule evidence from P3.
   - describe the alternative rule state for analysis.
   - do not invent missed-trade or hypothetical PnL; therefore the counterfactual verdict and outcome remain `UNAVAILABLE` unless future canonical rule-replay evidence is added.

3. `MANAGEMENT_EXIT_POLICY`
   - version 1 records observed management family alternatives only where explicit management evidence exists.
   - without ordered market evidence sufficient to prove an alternate exit, classify `BOUNDED` or `UNAVAILABLE`; no synthetic PnL.

### Aggregation
P4 snapshot publishes:
- total scenario count;
- exact/bounded/unavailable counts and coverage percentages;
- per-family sample counts;
- average delta metrics only over rows where the relevant delta is non-null;
- improvement/deterioration counts only for proven deltas;
- no recommendation language.

### API
Add GET-only localhost endpoint:
`GET /api/v1/phase7c/counterfactual-intelligence`

Accepted query parameters mirror P3 bounded reads (`days`, `symbol`, `limit`). Response sets `cache-control: no-store`. No POST/PUT/PATCH/DELETE route is permitted.

### Control Center
Add a collapsed-by-default card titled `P4 · Shadow / Counterfactual Intelligence` with always-visible:
- `READ ONLY` and `SHADOW ONLY` labels;
- exact/bounded/unavailable counts;
- evidence coverage;
- explicit `AUTO RETUNE: DISABLED` text;
- load/error state.

Expanded details show family summaries and warnings. No save/apply/retune control is allowed.

## P5 boundary
P4 must not create a recommendation engine. It may expose evidence and delta metrics only. P5 remains a separate future subsystem. No code in P4 may write strategy/risk/configuration or automatically apply parameters to LIVE.

## Safety invariants

`SHADOW_ONLY=true`

## Acceptance criteria
P3 source closure is complete when tests prove every P3 current Fast-Move representation is 10/10 and the read-only production verifier exists and is CI-validated. P3 production functional acceptance is complete only when the verifier passes on the production host after a controlled source rollout containing the closure patch.

P4 source delivery is complete when schema, evaluator, aggregation, GET-only localhost API, Control Center card, safety contracts, dedicated CI and canonical regressions are merged. P4 production acceptance is complete only after a later accepted runtime generation serves the P4 endpoint and passes read-only acceptance checks.
